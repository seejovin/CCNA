# Domain 1 authoring and audit notes

Completed 180 original questions: 20 each for Sets 02–10. Every fragment contains 16 single-answer questions, three two-answer questions, and one matching question. Every set assesses all 13 Network Fundamentals parent objectives. All 28 lettered Domain 1 children are represented across the new sets. The final questions contain 27 Foundation, 140 Applied, and 13 Challenge labels; these are editorial labels, not empirically calibrated difficulty measures.

The question bank is freshly authored from standard networking principles, not recalled exam items or commercial practice banks. Scenarios vary the required reasoning: source versus destination MAC learning; valid host boundaries versus address overlap; prefix extraction versus prefix membership; private-range membership versus interconnection consequences; physical compatibility versus loss budgets; full-duplex versus shared-medium behavior; link integrity versus congestion; configured state versus observed behavior; virtual isolation versus common dependencies. Repeated objectives deliberately recur for practice; these are not nine batches generated by substituting names or numbers into one fixed question template.

`author_domain1.py` is the literal authoring source. `domain1.json` is the final flat interchange array. `audit_domain1.py` checks schema, exact IDs, per-set domain counts, all parent and child coverage, response cardinality, unique prompts/options, and references. Its independent standard-library calculations cover 37 specific addressing, EUI-64, power, optical, capacity, and RF cases, recorded in `domain1-calculation-audit.json`. Address calculations use `ipaddress`; EUI-64 checks independently operate on bytes. Questions contain constructed outputs and conditions, not claims of executed labs or production measurements.

There are at least four output/configuration/calculation reasoning cases in every 20-question fragment, counting numerical scenarios embedded directly in question text. Optional exhibit objects are used where a display is useful; not every calculation needs a separate exhibit. All multiple-answer prompts explicitly require two answers. Single-answer key distribution is A=39, B=31, C=37, D=37. No unchanged choice set is deliberately reused between new questions.

Editorial review clarified a potential distractor ambiguity in CCNA5-008: an address with nonzero host bits and /64 could still identify the keyed prefix. Option D now uses an actually different fourth hextet. CCNA3-009 was rewritten to assess service-health failure with a retained anycast advertisement rather than repeating the original bank’s geographic-distance misconception. CCNA10-020 was changed from repeated component-role matching to interface-fault matching. Stem overlap review found only one pair above a 0.58 word-set Jaccard score: CCNA4-020 and CCNA7-020, which share matching instructions but assess different mechanisms (MAC switching versus TCP/UDP). No exact prompt duplicates occur within the 180 new questions or against Set 01. The anycast service-health reference was also narrowed to RFC 4786 section 4.4.1, Signalling Service Availability. An independent reviewer additionally ran 41 assertions across 40 numerical question cases and reviewed host/gateway and interface-counter interpretations; no further numerical or unique-key issue was found after the CCNA5-008 correction.

Source verification: the Cisco v1.1 blueprint was opened at https://learningcontent.cisco.com/documents/marketing/exam-topics/200-301-CCNA-v1.1.pdf. The final source catalog below includes reused established Set 01 references and newly opened primary material. Cisco subnetting, duplex negotiation, optical specifications, MAC tables, campus design, spine-leaf design, PoE, VRF-lite, NGFW, Meraki channel planning and encryption, TCP/UDP/IPv6/private-address/EUI-64/ULA/anycast RFCs, Docker, Linux manuals, Apple, and libvirt documentation were checked. New references include RFC 6598, RFC 4007, RFC 7217, Cisco IPv6 configuration, Meraki RF design/interference/throughput, and the Cisco QoS FAQ.

Some initial guessed legacy Apple, Cisco IPv6, and Meraki RF URLs did not resolve. They were replaced before final output by the verified current deep links listed below. Such failed candidate links do not appear in the delivered question bank. Reference sections are supporting concepts, not a claim that the vendor wrote the synthetic case. Repeated basic principles are independently explained rather than quoted; no substantial reference text was copied.

Scope limitations: no executable performance labs are included; no claim of Cisco endorsement, real-exam recall, calibrated pass prediction, or guaranteed exam outcomes is made. Operational assumptions (ordinary /30 host rules, expressly specified EUI-64 generation, per-port versus system PoE allocation, permitted output ports, no special filtering, and explicit optical limits) are stated where relevant. Documentation example prefixes are used for synthetic addressing. Current live exam delivery can differ from this requested v1.1 practice blueprint.
